## No prospect or client names in this repo

This repo is public. Prospect and client names, and anything found on their sites or documents,
never go in it: not in code, docs, specs, commit messages, branch names, or PR text. They live in
the private a11y-audit repo, with findings and per-client work under its `clients/` folder, which is

## The private desk

Since 2026-10-16 `/desk` uses the public pages' system: the `max-w-5xl page-wide` container, `PageHeading` for its H1, and in the desk repo's `desk.html` the heading scale's classes (`section-heading h-section` on each `h2`, `h-sub` on each `h3`; the scale is `.h-page`, `.h-section` and `.h-sub` in `globals.css`, which the heading components also use) and one table markup: `div.table-scroll` (a labelled, focusable region that scrolls on a phone) around `table.doc-table.desk-table`, whose label column is 28% in every table. Styles only live here; the content stays in the private repo.

`/desk` is a gated quick reference for research and live phone calls: pricing (a phone summary, unit rates, the full fixed-fee ranges, healthcare, vendor ACR, and the pricing method), before-we-start, recon, which rule and which date, the pitch, and the IDs buyers ask for. One login covers everything private: `middleware.ts` gates `/desk` and `/tools` (except the public `/tools/voice-critique`) with the signed cookie from `/login` (`SITE_GATE_PASSWORD`, `SITE_GATE_SECRET`), and every desk route checks the cookie again itself. Signed out, desk pages redirect to `/login` and data files answer 401. The login's default destination is `/desk`, and it only follows a `next` that is a path on this site. `/desk` is noindex, in neither sitemap, and linked from no public page.

**None of the desk's content is in this repo, which is public.** `lib/desk.ts` reads it at request time from private repos with `DESK_GH_TOKEN`, a fine-grained read-only token (Contents: read on `desk`, `fed-intel` and `state-intel`) stored as a Vercel secret, and caches each read for two minutes:

- `/desk` renders `desk.html` from `brianbeals/desk`, and `/desk/doc/<slug>` serves the full source documents from its `docs/`. That repo's README maps each section to its source file in iCloud `LLC/FL-VBE/Accessibility-Practice/`.
- `/desk/fed/<file>` serves the four fed-intel modules and `partners.json`, `status.json` and `a11y-market.json` from `fed-intel` `main`, by an allowlist of names. `/desk/fed` opens Module 1.
- `/desk/state/<path>` serves state-intel's built site from its `dashboard` branch, which that repo's Action force-pushes on every run. `/desk/state` opens `state.html`.

Without the token every desk route says it is not connected and shows nothing. The value is trimmed, and if it is not a single `github_pat_` or `ghp_` token the desk says "DESK_GH_TOKEN is malformed; re-paste it in Vercel" rather than GitHub's raw error (terminal output once got pasted in with it); a token GitHub refuses gets a plain message too, and the value is never shown or logged.

`/desk` has its own header (`app/components/DeskHeader.tsx`, picked by `HeaderSwitch.tsx` in the root layout): the public header's navy bar, stripe, sticky rules and Menu button, with the BB mark and "Brian Beals, LLC · Desk" linking the top of the desk, the sections as in-page links (Pricing, Before we start, Recon, Rules & dates, Pitch, IDs) plus State and Fed, and Sign out on the right; the site's own skip link stays first. The source documents and the dashboards, served as built HTML, carry the bar from `lib/desk-bar.ts` instead, with the same names and stripe and the current section marked `aria-current="page"`; it wraps on narrow screens rather than collapsing, since React does not render those pages. On the Fed dashboards a light strip under that bar links the federal (Section 508) pitch at `/desk#pitch-federal` (2026-10-17); it lives in `lib/desk-bar.ts` because fed-intel's weekly Action rebuilds its pages. **Sign out** is `/logout`, which clears the gate cookie and lands on the public home page. For a local check without a token, serve the three clones over HTTP from a scratch folder (`python3 -m http.server 8765 --bind 127.0.0.1`) and start the site with `DESK_LOCAL_URL=http://127.0.0.1:8765`; never set it on Vercel. Account Intel, the tool the gate was first built for, was retired on 2026-10-15 with its `/api/account-intel` routes; its scope note is in `docs/history/`.

**Copy buttons** (2026-10-17). `app/desk/DeskCopy.tsx` adds a real "Copy table" or "Copy email" button above every element `desk.html` marks `data-shareable="true"`, so a new client-facing table needs only the attribute (plus `data-copy-label`, which goes into the button's accessible name, "Copy table: Fixed fees"). ## Free test (built, flag off)

The site's half of the free automated test (spec: `docs/free-test/SPEC.md`; the engine is a11y-audit
`free_test/`). `/free-test` is the form: website and work email, Cloudflare Turnstile checked on the
server, a honeypot, and the contact form's error summary. `/free-test/confirm?token=` and
`/free-test/approve?id=&sig=` are the links the engine emails, each a page with a button, so a mail
scanner that opens every link can't confirm or approve anything; `/free-test/confirmed` follows a
confirmation. Each request, confirmation and approval is one signed message (HMAC-SHA256 over the
JSON line, `lib/free-test.ts`, byte for byte the engine's format) sent through Resend From
`freetest@forms.brianbeals.com` to brian@brianbeals.com with the subject `[free-test] <type>`, which
the Proton filter files into the "Free Test Requests" queue. The site keeps nothing. Once the fields
are well formed and Turnstile passes, every request ends in the same "Check your email" message; a
tripped honeypot and the in-memory rate limit send nothing and say the same.

Off unless `FREE_TEST_ENABLED=true` and `FREE_TEST_SECRET` (32+ characters, the engine's secret),
`TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY` and `RESEND_API_KEY` are all set: off, every free-test
route is a 404, and /scanner, `sitemap.xml` and `/sitemap-page` don't mention it (they read the flag
at build, so set it and redeploy). `freetest@forms.brianbeals.com` must be added as a Resend sender
before the flag goes on. The form's copy says Brian reads each report first; change it if the engine's
`REVIEW_MODE` goes off.

Local end to end: `FREE_TEST_OUTBOX=<folder>` (refused on Vercel) writes each event there as an
`.eml` instead of sending, and the engine reads the same folder with `FREE_TEST_QUEUE=dir:<folder>`,
mail to Mailpit on 1026 (`FREE_TEST_MAIL=smtp://127.0.0.1:1026`, never 1025, which is Proton Bridge).
Cloudflare's published test keys pass Turnstile on localhost (site `1x00000000000000000000AA`, secret
`1x0000000000000000000000000000000AA`). Run that way on 2026-10-17 with a browser driving the form:
request, confirmation, a scan of brianbeals.com, the review draft, approval and the report all went
through, 19 of 19 checks; axe (WCAG 2.1 A and AA) found nothing on the new pages, the error and
success states, in light and dark, and the page fits 320px (Turnstile drops to its compact size below
380px).

## Deploy

Pushes to `main` auto-deploy via Vercel. There is no staging gate and no date gate: whatever lands on `main` is public within about a minute. The `publishedTime` and `datePublished` values on an essay page are display text and JSON-LD only. They control nothing.

## Publishing an essay on a schedule

Essays ship on a two-week Saturday cadence, and they go out automated. Never push a finished essay straight to `main` ahead of its slot; that publishes it immediately, carrying a date in its own future.

The routine is a one-shot workflow plus a branch:

1. **Arm the scheduler on `main`.** Add `.github/workflows/publish-essay-NN.yml` with a `schedule` cron for the target date and `workflow_dispatch` as the manual fallback. Commit it to `main` on its own.
2. **Build the essay branch from that `main`.** Branch name `essay-NN-slug`. It carries the new `app/writing/<slug>/page.tsx`, the new entry at the top of the `app/writing/page.tsx` array, and a `git rm` of the workflow file added in step 1.
3. **Wait.** On the cron the workflow merges the branch into `main`, which publishes the essay and removes the scheduler in the same commit. Nothing is left behind to fire twice, and there is nothing to clean up.

Two things that have bitten this routine:

- **Schedule a few minutes past the hour.** Essay 6's cron was `0 13 25 7 *` and GitHub dropped it outright; top of the hour is the heaviest window on Actions and scheduled jobs there are shed first. That publish had to be fired by hand from the Actions tab. Use `:07` or similar. Actions cron is best-effort regardless: essay 10's `:07` cron still fired 3h16m late on September 19. Arm a second cron 30 minutes later as a backup (the merge is idempotent) and treat `workflow_dispatch` as the reliable path. The n8n essay dispatcher in the `n8n-automation` repo finds any armed `publish-essay-NN.yml` on `main` and dispatches it.
- **Never cut the essay branch from a reverted commit.** If a publish commit was reverted on `main`, that commit is already an ancestor of `main` and merging a branch containing it does nothing at all. Branch from current `main` and re-apply the files as a fresh commit (`git checkout <publish-sha> -- app/writing` is the simplest way).

Because the workflow deletes itself on every publish, `.github/workflows/` is normally empty between essays. An empty workflows directory is the expected resting state, not a sign the routine was lost. This section is the durable copy of the routine; the workflow file is disposable.
